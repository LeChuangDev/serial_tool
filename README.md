# Leeco-Serial 樂創串口调试终端

基于 PyQt6 的跨平台串口调试助手，深蓝工业风界面，面向嵌入式调试（ESP32 / STM32 / 串口模块）的日常使用。

当前版本 **3.0**。相较 2.x，重点是三件事：**掉线能自己连回来**、**界面重排让接收区回到主视野**、
**把调试时真正要看的东西（时间间隔、错误关键字、端口身份）直接摆到界面上**。

---

## 一、v3 主要变化

### 1. 自动重连（核心新增功能）

USB 转串口拔插后 **COM 号经常会变**（COM3 → COM15）。只按端口名重连在真机上几乎必然失败，
因此重连按"设备身份"而不是"端口名"找回设备：

```
读取持续失败 2s → 判定链路中断 → 进入重连流程 → 指数退避 → 扫描端口 → 身份打分 → 重新打开
```

| 匹配依据 | 分值 | 说明 |
| --- | --- | --- |
| 端口名 + VID/PID 全同 | 100 | 同一设备、同一口 |
| 仅端口名相同（无 USB 信息） | 85~90 | 老式板载串口 |
| 序列号 + VID/PID 全同 | 80 | **换了 COM 号也能找回**（CP210x/FT232 有唯一序列号） |
| 仅 VID/PID 相同 | 60 | 廉价 CH340 常无序列号，退而求其次 |
| 描述完全一致 | 40 | 最后兜底 |

退避与上限：首次冷却 1.2s（等 USB 重新枚举），之后 0.8s → 1.6s → 3.2s → … 封顶 15s，
默认最多 10 次（`config.RECONNECT_MAX_ATTEMPTS`，设 0 为无限）。每次尝试的等待时间带 ±20% 抖动，
避免多开时同时抢口。状态栏实时显示「自动重连 3/10 · 1.4s 后重试」。

设计上的两个刻意选择：

- **重连期间不弹模态框**。失败只写进接收区并继续退避，否则用户离开工位时重连会被对话框卡死。
- **区分"掉线"与"用户主动断开"**。只有非用户操作的断开才触发重连，点「断开」不会自己连回来。

### 2. 界面重排

```
┌ 连接栏（端口 / 线路参数 / 自动重连 / DTR·RTS·复位）──────────────┐
├ 会话 · 显示 · 统计 ┬ 接收（速率图 + 波形 + 查找）──────────────┤
│  （窄栏，只读）    │                                            │
│                    ├ 发送 [单条] [多条] [文件] ─────────────────┤
└────────────────────┴────────────────────────────────────────────┘
```

- 串口参数从左侧竖排六行改为**顶部两行连接栏**，连接动作紧跟参数，符合串口工具的肌肉记忆；
- 左侧窄栏只放"会话身份 / 显示选项 / 统计"，接收区因此拿到整块主视野；
- 发送区改为**三页签**：多条发送表格不再长期挤占单条发送的输入框；
- 文件发送从"状态栏一行小字"升级为独立页签：文件选择、分块间隔、进度条、取消按钮。
- 下拉框宽度按**内容下限**而非固定像素，选中 `XON/XOFF`、`1500000` 也不会显示成 `XON/X…`；
  最小窗口 1120×680 由"所有字段都能完整显示"反推，并有 `TestLayoutAudit` 守着不再退化。

### 3. 调试向的新能力

| 能力 | 为什么加 |
| --- | --- |
| 时间戳三模式（时钟 / 相对连接时间 / **包间隔增量**） | 排查轮询周期、超时重发、卡顿定位，`+50ms` 比绝对时间有用得多 |
| 关键字高亮（字面量 / 正则，可编辑，JSON 持久化） | `error`、`ready`、`reset` 一眼可见，不必在 10 万行日志里 Ctrl+F |
| 会话卡片显示 VID:PID / 序列号 / 厂商 | 插着三块 CH340 时，靠这几行才能确认自己在调哪块板 |
| 行尾选择（无 / `\r\n` / `\n` / `\r`） | 从"新行"复选框升级为四选一；二进制协议必须能选「无」 |
| 端口参数记忆 | 每个 COM 口单独记住波特率/校验/流控，换口不用重设（类似 PuTTY 会话档案） |
| 连接后自动记录日志 | 无人值守跑长时间测试时，不会忘记开日志 |
| 发送 BREAK（TX 中断 250ms） | 部分 MCU 的 ISP / 调试模式入口 |
| 文件发送限速（分块间隔 ms） | 慢速 MCU 全速灌入会丢字节，限速比"发完再查"靠谱 |
| 统计卡（收/发/帧数/错误/峰值/时长） | 读异常、写失败次数直接可见，不再只看总字节数 |
| 发送框 ↑/↓ 翻历史 | 调试时反复发同几条指令 |

## 二、功能清单

**收发**
- ASCII / HEX 双模式收发，毫秒级时间戳（使用数据包真实到达时间）
- 增量解码：UTF-8 / GBK 多字节字符被包边界切开也不乱码
- 按包 / 按行两种断行模式，长行保护（缓冲区上限自动冲刷）
- 定时发送、预设命令库、发送历史、多条发送列表（逐条延迟 + 循环）
- 文件发送：分块流式 + 写队列背压，进度条、限速、取消
- 追加 Modbus CRC16、TX 回显、发送 BREAK

**串口**
- 全参数：波特率（含自定义 50~12000000）、数据位、停止位、校验位（含 Mark/Space）、流控（无 / RTS-CTS / XON-XOFF）
- 端口热插拔检测、自然排序（COM9 在 COM10 前）、蓝牙虚拟口过滤、下拉显示设备描述
- DTR / RTS 电平控制，ESP32 一键复位（RTS 低 150ms，UI 零阻塞）
- 断线自动重连（按 VID:PID/序列号找回，指数退避 + 次数上限 + 手动接管）

**观测与留存**
- 接收区实时字节波形、收发速率迷你图（60 秒）
- 配色/字号可调（Ctrl+滚轮）、Ctrl+F 查找、右键菜单
- 日志按日归档（跨天自动切换）、HEX 原始数据导出、接收区另存
- 配置导入/导出（JSON）、参数记忆、端口档案
- 结构化运行日志 `logs/app.log`（2MB × 4 滚动）+ 全局异常兜底（落盘 + 弹窗）

## 三、运行

```bash
pip install -r requirements.txt
python main.py
```

- CH340 等 USB 串口驱动安装包见 `drivers/`

## 六、架构约定

1. **UI 线程不碰 `serial.Serial`**：写数据、DTR/RTS、BREAK 一律经命令队列交给工作线程。
2. **可测逻辑与 Qt 解耦**：`ports` / `reconnect` / `highlight` / `timestamps` / `recv_pipeline` 都不依赖控件。
3. **配置只经 `SettingsStore` 读写**：避免 QSettings 类型漂移（注册表可能读回字符串）。
4. **错误分级**：`open_failed`（需弹窗）、`link_lost`（触发重连）、`error`（写接收区）三条通道分开。
5. **静默失败为零**：所有异常至少落一条日志。
6. **重连不阻塞 UI**：状态机只输出"到点/未到点"，扫描在后台线程，打开在串口线程。
7. **测试不碰真实配置**：`tests/conftest.py` 把 `QSettings` 重定向到临时 INI 目录，并在每个用例前清空。
   否则用例间的隐式状态传递会制造"单跑通过、整套失败"的顺序依赖。

## 八、日志说明

- `logs/app.log`：程序运行日志（错误、连接、重连事件），滚动归档。
- `logs/serial_YYYYMMDD.log`：勾选「记录到文件」或「连接后自动记录」后写入的接收数据，带绝对时间戳，跨天自动切换。
- 菜单「文件 → 保存接收日志」另存当前显示内容；「导出接收数据(HEX)」导出原始字节。

## 九、已知限制

- 重连基于 USB 身份：**没有序列号的 CH340 换口后只能按 VID/PID 匹配**，同时插两块同型号时可能选到另一块。
- 重连依赖 `serial.read` 抛异常来判定掉线（2s 阈值）。个别虚拟串口驱动拔出后不抛异常，
  此时只能靠 5s 一次的端口扫描发现"端口消失"，重连会慢 5 秒左右。
- 大文件发送进度反映"已入队字节"，不是"设备已收字节"；对端无流控时真实到达时间会略滞后。
- 未在真实硬件上做 921600 长时间压测与 20 次快速插拔循环（当前环境无硬件）。

## 十、后续可加功能（按性价比排序）

**P0：调试闭环缺失的一环**
1. **Modbus RTU 组包/解析**：填从站地址/功能码/寄存器，自动算 CRC 并解析响应（XCOM 的核心卖点）。
   现有 CRC16 只解决"发"，没解决"看"。
2. **脚本/宏（expect 式）**：发送 → 等匹配 → 再发送，可存成文件回放。Tera Term 靠这个成为回归测试首选，
   也是把"手工点点点"变成"可重复验证"的关键。
3. **发送快捷键绑定（F1~F8）**：预设指令一键发出，联调时少敲键盘。

**P1：能力边界扩展**
4. **TCP/UDP 调试**（串口 + 网络同窗）：SSCOM 长期被留在工位上的主要原因；透传模块调试必然要跨串口与网络。
5. **数据绘图**：把 `value=123\r\n` 这类文本解析成曲线（COMTool / Serial Studio 的做法），
   比看数字滚动快一个数量级。
6. **多串口同时打开**：对照测试两块板子（YAT 的强项），需要把 worker/端口状态从单例改成会话集合。

**P2：工程化补充**
7. **接收侧环形缓冲落盘**：长时间挂机采集时把原始流写文件而不是只留内存 16MB（SSCOM 的 180MB 内存问题就是反面教材）。
8. **协议插件机制**：把帧解析做成可加载模块，避免主程序随协议增长而膨胀。
9. **打包分发**：PyInstaller 单文件 + 版本信息 + 图标，交付给同事时不用装 Python。
